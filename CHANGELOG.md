# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

PaintOmics AI has not been cut as a numbered release yet, so everything since
PaintOmics 4 is listed under Unreleased. Entries reference the pull request that
merged them where one exists.

## [Unreleased]

### Added

- Grape gene ids from older genome versions now map on `vvi` once its table is applied: 12X ids (`VIT_00s0125g00090`, about 17,000 genes) and PN40024.v4 ids (`Vitvi18g00828`, about 8,200) through Ensembl Plants' own link to an NCBI gene, and NCBI's locus tags (`VIT_00032725001`, 17,400). Where the id and the NCBI gene are both on numbered chromosomes, a link is kept only where the neighbouring genes put that gene where KEGG has it (67 left out, such as `VIT_05s0062g01430`, linked to a gene on another chromosome); 8 12X ids on a nuclear chromosome linked to a plastid or mitochondrial gene are left out too (`VIT_13s0019g02630`, linked to psbA), and about 1,100 ids on unplaced sequences are kept without that check. Until now only the PN_T2T form (`Vitis01g00541`) mapped. The table is `identifier_aliases/vvi.tsv.gz`, with its sources and limits in the README beside it.
- Gene ids from another genome version, on request from users whose files mapped nothing: maize B73 RefGen_v4 ids (`Zm00001d...`, about 27,800 of 44,100 genes reach KEGG) and pea Cameor v2 ids (`Psat.cameor.v2...`, about 22,000 of 49,700), and 3,192 sorghum Ensembl genes gain the link to KEGG their NCBI locus tag gives them. The tables ship in `AdminTools/scripts/common_resources/identifier_aliases/` with a script that regenerates them, and the default installer applies them during a build, so a server that has them keeps them through every rebuild. Each row records its evidence, and about 8,700 pea rows are marked as a cross-cultivar sequence match, not a published correspondence. A maize or pea alias reaches exactly what the gene it names reaches and is never walked through to anything else; sorghum rows are walked through, so those genes' transcripts, proteins and UniProt accessions now reach KEGG too. The installer refuses a row when two gene-level ids claim one target, when a bridge row's target reaches more than one KEGG gene, when the alias names two targets, or when the name already reaches a KEGG gene its target does not. Transcript ids of another genome version stay unmapped: on the organism they belong to, the Step 2 message tells the user to remove the suffix, and on any other to check the organism. Sources and credits are on *Supported identifiers*. The step 1 organism hint now recognises Cameor v2 ids and maize v4 transcript ids.
- A **Download** button on the Step 4 **Global heatmap** panel, offering the whole heatmap as a high-resolution PNG or an editable SVG: every omic drawn, side by side, under its heading and colour scale, with the clustering, the relevance and per-condition stars, row labels and condition names written out in full, a title naming the pathway and job, and a key for the stars. It is drawn on white in either theme and built in the browser. Until now the button sat commented out over a `download()` that threw "Not implemented", and the only way to keep a heatmap was a screenshot of the part that fitted on screen.
- A user-guide page, *Comparing three or more groups*: a three-group mouse RNA-seq and lipidomics example (simulated, with the changed pathways listed), an R script that turns raw counts and lipid intensities into one log2 fold-change column and one relevant list per contrast with DESeq2 and limma, and annotated screenshots of every step on paintomics.org. *Preparing your data* now says how a relevant-features header is recognised and why a `#` header leaves a two-column file a pair list, and the FAQ answers whether more than two groups can be compared.
- A step 1 organism hint: the moment a gene-based data file is picked, PaintOmics checks which installed organism its identifiers fit -- from the identifier convention when it is species-specific, otherwise by asking the mapping index of the commonly used organisms -- fills an empty organism field, and flags a chosen organism the identifiers contradict, with one click to correct it. The step 2 "nothing matched" message names that organism too.
- Five checks every walk interpretation must pass before it is rendered, each a verdict stored with the walk and shown as a chip with its numbers: the walk finds more modules than permuted data does and never steps through a currency metabolite (every edge tiered mechanism or association); the title and summary use a mechanistic verb only where a mechanism statement stands behind it, else code writes a neutral title; feedback reporters and true inhibitors are read the right way round on a curated panel of forty-one regulators, with a sign-flipped counter-hypothesis; every cited paper carries its organism, system and scope from MeSH, an out-of-context paper must be named as such where it is cited, and the paper agent checks the citing sentence against its passage; and the walk is anchored to the perturbed gene the design names, given its known transcription-factor targets (`omnipathInstaller.py --tf-targets` writes `mapping/tf_targets.tsv` from CollecTRI and TRRUST) with every module labelled by its distance and the perturbation stated in the header. A harness (`cli --five-checks`) measures the five offline at production temperatures and reports ranges; a simulated Pten knockout dataset serves the anchor test.
- AI interpretation as an agentic graph walk: one network per organism from KEGG, Reactome (complexes and sets read as their proteins) and OmniPath with the job laid over it, a walker with six tools (scan, plan, step, jump, note, stop), a Writer whose statements separate what the pathway draws from what is built on top of it and cite only papers it retrieved in PubMed's best-match order and read, code and model checks on every statement, and a Narrator that writes a checked Results section with its citations numbered in order of first use. The walk over the whole network is the job's interpretation, queued when Step 2 finishes and shown in the AI panel with its legs, statements and references; a Step 4 **Walk** column walks one pathway on its own map with the design card editable before the walk and the legs drawn on the diagram; the chat reads the walk and can walk a few steps from a gene. Walks share the analysis queue under a cap (one fewer than the workers, two per job), a read-only job's walk is its owner's to replace, and a walk stops when its job is deleted. Agents work in parallel inside a ten-minute budget: a planner, one walker per seed, one Writer per part of the chain, and a paper agent that reads every cited paper and returns the passage stating the claim, which code finds in the paper and the page shows under each reference with the section it came from. On the example job the interpretation cites 26 papers in a 1,900-word Results section in under five minutes. Statements and Results name genes instead of calling them a cluster. A planted-module evaluation and a command-line runner with an HTML report come with it.
- A design card read from the experiment design and the user's column headers, which every AI prompt carries: whether the columns are time points, ordered values or unordered conditions, which omics have no column labels, and the guidance that follows (trajectory words only on an ordered axis). The chat tool `get_gene_timecourse` is now `get_feature_values`, which prints each layer under its own labels and never borrows another omic's.
- Ensembl gene, transcript and peptide identifiers for every installed species whose organism Ensembl or Ensembl Genomes annotates. A genebuild registry (`AdminTools/scripts/common_resources/ensembl_genebuilds.json`) tells the default installer where each organism's cross-reference dumps live, and `ensembl_census.py census|verify` reports, per species, which identifier tables exist and what fraction of sampled Ensembl gene ids reach the KEGG identifier table through the real mapper.
- An AI input-format converter that checks every upload against the server's contract, offers one-click deterministic repairs for mechanical faults, and can rewrite a file the analysis cannot read (#67, #72).
- The MORE regulatory model behind a model chooser in Regulatory Omics, offering PLS1 and MLR on `more-rs`, the Rust engine (#44, #166).
- A Step 3 regulator-target network drawn with Cytoscape.js, with free layout, per-condition colouring, search, spotlight, side panel and exports.
- Regulation-per-condition tables beside that network, a "Find in pathways" hand-off from them into the pathway view, and a user-selectable per-omic minimum variation filter for MORE.
- Multi-condition designs: analyses run across any number of conditions rather than two, with per-condition significance stars in the Step 4 heatmaps, in Metabolite Hub and in Class Activity, and a Stouffer weights panel for the combined p-value.
- Replicate-to-sample aggregation in both the pathway visualization and MORE, with the experiment design drafted from your column headers before a job exists.
- A metabolite class activity analysis drawn as a levelled class map, testing whether a class responds on replicates when the data has them (#96, #101, #105).
- A Step 2 disambiguation step that lets you choose which compound an ambiguous metabolite name meant (#88).
- A metabolite hub network derived from the KEGG graph and drawn in the interface (#89).
- An evidence overlay that draws MORE relationships on the pathway diagram as a provenance-labelled layer (#52), including regulators the diagram itself does not print (#84).
- OmniPath as a fourth pathway database source (#43), rice (osa) as a MapMan species (#42), and installation of custom species from a gene-to-KO annotation table.
- Bundled example datasets built from a seeded, manifest-driven generator, with the pathways the enrichment should recover listed alongside the files, and **Load example** for Regions2Genes, miRNA2Genes and MORE as well as pathway acquisition.
- A dark theme with a toggle in the header, a contents sidebar on the results page that follows the database tab in view, and an organism picker that ranks results by what was typed rather than by prefix match (#75).
- A Docker Compose deployment (nginx/TLS, application, MongoDB), a post-deployment smoke test, an operator runbook, species installation from the command line, and a view of the requests users have sent in, in the admin panel (#54).
- Continuous integration: a pull-request gate, a nightly regression run against recorded baselines, staging deployment on merge, and an on-demand profiling workflow.
- Test coverage that had not existed: an import smoke test over every tracked module, an end-to-end enrichment run against a real installed species, the real R backend instead of a double, and a check that an edited asset gets its cache marker bumped.

### Changed

- The pull-request check now runs the client's JavaScript tests in `PaintomicsClient/tests`, which no workflow ran before. One of them had been failing since August because it still expected a design-file rule that was removed on purpose; it now tests the rule as it stands. The mail-outage server test no longer depends on which organisms the machine's KEGG data holds: it brings its own list (it failed wherever Fusarium oxysporum was installed). The example calibration test no longer fails on a target pathway whose KEGG name differs from the one the example records (mmu04142: recorded as "Lysosome" with 136 mouse genes, "Lysosome biogenesis" with 253 on paintomics.org's KEGG). For such a target it skips the 50% floor and says why, and it still fails if the planted genes left are under 50% of the recorded size. That test still reads the machine's KEGG data, so a target that grows under its old name still fails it, and where the data has no Ensembl mapping (as in CI) its KEGG checks still skip.
- A walk interpretation the five checks held back is hidden by default instead of withheld: a note names the checks it did not clear, and **Show the interpretation anyway** opens its Results, references and statements under a warning to read them as hypotheses drawn from the walk and the cited papers, not as findings, in both the AI panel and the Step 4 Walk column; the choice holds for that walk while the page is open, and the chat is told the text is there to open. The *Not a graph artifact* check keeps its pass rule and its measured numbers but reports what it could and could not tell: it now stores the measured and relevant counts, how many edges join two relevant genes against its own fifty permutations (counted by hand on a bladder cancer job: 45 against 27.8 expected over 200 permutations, p = 0.10, where the check's walker found 1 module against 1.1), and `untestable` when no three relevant genes are connected, so no module can form (hsa05219's 4 relevant genes of 22 touch none). Its reason no longer says the data "has no structure a walk could find", and an untestable chip is amber with a "?". On a pathway walk (the Step 4 Walk column) that check is now advisory: a failure shows amber ("!", or "?" when untestable) with a reason saying it hides nothing, and only the other four checks can hide the text, because the user opened a map the enrichment test already flagged (Bladder cancer, p = 0.018) and one map's few relevant genes leave the check little or nothing to measure (hsa05219 is untestable; the FoxO map withheld every run, real ones included). The network walk keeps the blocking rule, which is where its rendering measurement was made, and a pathway walk sealed earlier and held back by that check alone shows without being walked again. Only the permutation half of that check is advisory: a walk that stepped through a currency metabolite (ATP, water, NAD) still fails it outright, red and hidden by default, on either kind of walk. An untestable check's hover says when fewer than three relevant genes are on the map, and the offline harness re-seals its records with the shipped rule, so a pathway re-measurement reports what users see. A walk that also stepped through a currency metabolite keeps the null's reason beside that one, which used to replace it.
- The CSIC gateway's `default/llm` alias (on 2026-09-30, Qwen3.8-Flash-Next) was measured as the model for every LLM call against the pinned `deepseek-ai/DeepSeek-V4-Flash-0731` snapshot, on the same code and the same STATegra example. The alias kept 1 statement and cited 2 papers; the snapshot kept 8 and cited 11. Its thinking mode made it worse: every walk ran into its time budget with nothing kept. So the snapshot stays the model, with the alias as its fallback. `AI_CSIC_MODEL=default/llm` still switches a deployment over, and the fixes that made the walk run on it are kept. `test_every_llm_call_asks_one_model` checks that the template, compose, both env examples, the gateway check and the CI review all name one model.
- A front-end pass of 198 small fixes across every screen: the header, menus and message dialogs; the landing page; Step 1 upload; Step 2 matching; the Step 3 results; the Step 4 pathway view; the AI panel; and the account, tools and storage pages. Most are alignment, spacing and type set in the app's own font rather than Neptune's; dark-theme colours that fell below readable contrast; keyboard and screen-reader access (icon-only controls that were unnamed or unreachable, a collapsed AI panel that stayed in the tab order, nav pills whose accessible name was their whole dropdown); grid columns and toolbars that clipped at 1024px; and wording that promised what the server does not do, such as an AI conversion on a server whose converter is off. Each change has a before/after capture in the pull request's report.
- Everything that sent people to paintomics.uv.es now sends them to paintomics.org, the public instance since the 2026-09-07 cutover: the README badge and link, the security policy, the citation file, the bug-report and organism-request issue templates, the terms and conditions page and the maintainer docs. A guest session shows the address the server stored, returned with the credentials, instead of one the client assembled from a hard-coded domain, so a deployment can name its guests under its own host without splitting the stored address from the displayed one. The "RGmatch example data" entry in the Help menu is gone: it linked an archive that left the repository in #170 and that neither instance serves.
- The application is renamed PaintOmics AI, the successor to PaintOmics 4.
- Navigation moved into the header and the left rail was removed.
- The interface runs on one token-based design system for surfaces, shapes and type, with a single typeface and WCAG AA contrast throughout; the landing page, the application mark and the account dialogs were redrawn, and the ExtJS dialogs, tables and upload controls modernized.
- The running-job spinner was replaced with a progress bar that only moves forward and reports what the job is doing.
- The heatmap colour scale was rebuilt against the range the data actually occupies, and the same ramp now paints the pathway diagrams (#63, #92).
- The platform moved to Python 3.11, Flask 3, and pymongo 4 against MongoDB 7, with the imaging and HTTP stacks upgraded onto versions carrying their security fixes, and dependencies declared in one pinned `requirements.txt` at the repository root.
- The analysis pipeline was profiled and made faster: batched cross-reference lookups, one shared fork-aware MongoDB client, a cached GTF annotation, and metagene R scripts run per omic in parallel (#33).
- Step 2 was rebuilt as one module system — a databases matrix, a levelled class-activity pair, and compound disambiguation inside the grid (#111, #114) — and Browse now lives inside the file field (#110).
- Every Step 1 file row now says whether the job requires that file (#108), and the database checkboxes are drawn from what the server has actually installed.
- Jobs are kept for as long as the interface says they will be, and no longer (#65), and the contact address is now `paintomicsai@gmail.com`.

### Fixed

- Two Step 3 cluster slider requests on one job, sent close together (for one omic or two), ran at the same time: the first to finish removed the folder the other was writing its pictures into, so the other failed and its new clusters were lost, and each could store its own copy of the job's pathways over the other's. Requests on one job now take turns (a Step 2 of that job waits too), each works in a folder of its own, and each starts from what the one before it stored. The log also stopped writing one line per feature in Step 2 and one per pathway when the slider is moved: the example job wrote 33,085 lines (7.5 MB) through Step 2 and two slider moves, now 272 (37 KB).
- On a job whose relevant features file has one column per condition, Step 3's adjusted combined column (*Combined pValue (…) [FDR BH]* and *[FDR BY]*) was not the correction of the combined p-value beside it. The combined column shows the combination of each omic's Global p-value, while the adjusted column showed the correction of the first condition's combined p-value, and a category filter recomputed it from the combined column, so the column changed meaning on the first filter: on the example *Gene expression — per-condition relevance*, hiding one KEGG pathway whose p-value is 1 moved it by up to 1.0, and 56 FDR BH values crossed 0.05. New jobs store the correction of the combined column, over the same pathways as the other FDR columns, and the same filter now moves it by at most 0.0011. On that example 228 of 3,988 adjusted combined values change, all downward, some by nearly 1 (a pathway whose combined p-value is 1.2e-23 read FDR BY 1 and now reads 3.8e-21), and the pathways under FDR BH 0.05 go from 17 to 45 for each combined method. On the five other examples that run Step 2, whose relevant features file is a single list (four of them have 6 or 36 conditions), nothing changes: there the first condition's combined p-value is the combined column. The network still reads each condition's combined p-value and its own correction. Jobs already stored keep the value they were stored with; on a job with one relevant column per condition, while a filter is applied the column shows the correction of the combined column over the rows left, and removing the filter brings the stored value back, so run such a job again to get the new value.
- The **From miRNA to Genes** tool page hid the box *Automatically select relevant associations using correlation*, so its gene expression file, Report, Score method, Selection method and Filter cutoff sat greyed out with no way to turn them on, and a run with your own files always needed a relevant associations file, while the page's help described those settings and never named that file. The page now shows the box as a Step 1 card does, unticked at first, with the same settings and defaults, so a run that leaves it unticked sends what it sent before. Its gene expression file is uploaded or taken from My Data; *Use a file from other omic*, which reuses a file from another Step 1 card, is not offered there, since the page has no other card and a file picked that way was never sent. The help says the form needs one of the two files and names each setting. Separately, Step 1's message for a lost identifier mapping worker ended "Please try again, and upload smaller files if it persists.", just above the error dialog's own "retrying in the browser will not help"; it now ends after saying why a worker is lost, as Step 2's does.
- Walk readings and kept statements quoted a neighbour's heat score as if it were the user's measured value: the walker printed a neighbour as "rrm1 r=0 2.43", and a reading wrote "Gene expression on rrm1 shows log2FC +2.43 (relevant), a strong induction" where the user's value is +0.12, not relevant (15 of 19 network walks in the 31 Oct round; on a zebrafish job two such statements were kept and the Results section was lost when its check removed them). The heat is now labelled ("rrm1 r=0 heat 2.43"), a reading, note or stop quoting a value no layer the walker can read holds is refused with that node's layers printed, and the Verifier sends back a statement quoting a value that neither its nodes' layers nor its cited papers hold, naming the node and its real values. A value is the user's when it is in the layers of any node whose layers the walk was shown, not only the nodes it stepped onto: counting the chain alone dropped true statements such as "Gli2 (+1.75) and Gli3 (+1.75)", values of neighbours the walker had read. A value given to a node whose heat it is, though another node holds it, is refused too, and so is a heat copied bare beside a layer's own words ("Ccc Gene expression 2.43"), continuing a measured list ("Log2FC of 0.10 and 2.43") or signed after the word ("rises under heat (+9.99)"); "heat shock" and "heat stress" no longer read as the heat score. A dose or time point ("0.25 mM", "0.25 h") is never read as a misquoted heat, and values the walker is shown in a refusal may be quoted on its next try. A list that names each node before its value ("Vegfc +1.94, Vegfd 1.93") is held to the check as one list, and a list of heats ("the hottest nodes (Ephx1 3.79, Cyp2f2 3.21)") is not; a number after the word heat ("the highest heat in the graph (3.70)") and one after a word that described the value before it ("Jag1 (+0.62) up, while … at 2.59") are no longer refused, and a heat of zero is printed "0.00", never "-0.00".
- Moving the Step 3 cluster slider for one omic deleted the cluster pictures of every other omic and database in the job, so in a job with "RNA" and "Proteins", changing the number of RNA clusters on the KEGG tab left the Proteins cluster pictures, and RNA's on the Reactome tab, as broken images. It also deleted any pathway picture exported as PNG into the job's folder. The slider now replaces only the pictures of the omic and database it recomputes. A Step 2 run still clears the old pictures of every omic, so going back and running Step 2 with fewer clusters leaves none from before.
- **From miRNA to Genes** told a run that finished without doing all it was asked (no score without gene expression, the retired selection `fc`) only in the first line of `genesToMiRNAFile.tab` inside the results archive. The tool page now shows that note first, as a warning titled *miRNA2Genes finished, with a note*, and Step 1 shows it on the omic's card and again once Step 2 opens. With Report *Only relevant features (e.g. DE)* the other miRNAs were never left out, though the tool page said they were ignored and the Report help said only the differentially expressed were considered: every pair stays in the results with its values under both choices, and Report only decides whose pairs can be marked relevant. The same was true of the correlation cutoff, which the tool page said filtered the targets and decided which genes were finally reported: it marks pairs as relevant and drops none. The help now says that for both, and a run where Report can mark nothing, because no relevant regulators file was given or it names none of the paired miRNAs, now says so. A score method other than kendall, spearman, pearson or `fc` (which the form never offered, and which runs with no score as before), sent by a hand-made request, crashed the run with Report error ("could not convert string to float: 'None'"); it is now refused as an input problem that names the three.
- The welcome dialog said "PaintOmics AI runs on Supercomputador Drago (CSIC)" on every server, including paintomics.uv.es, which runs at the Universitat de València. Each server now says where it runs from its own setting, `PAINTOMICS_HOSTED_BY`, which keeps paintomics.org's sentence by default; a server whose setting is empty, or missing from a hand-kept `serverconf.py`, names no host. The server log also no longer takes the debug lines of the scheduler ("Looking for jobs to run", "Next wakeup is due"), the AI client libraries, the time zone lookup and the image reader; their warnings and errors still go to the log, and PaintOmics' own lines are unchanged. paintomics.uv.es's uWSGI log, which nothing rotated and which had reached 7.7 GB, is now moved to `uwsgi.log.1` once it passes 100 MB, replacing the copy moved there before (`paintomics4.ini`). What filled it is not established: the scheduler wakes once a day and writes a few lines each time, far too few on their own.
- From miRNA to Genes offered the selection method "by max. fold-change of feature expression", which computed no fold change: it kept a pair when its correlation with the target gene was above the cutoff, the same as "by positive correlation". The form no longer offers it, and the cutoff's help no longer reads "Threshold for the correlation or fold change". The selection method's help and the cutoff's now say which way each selection keeps a pair: a correlation below the cutoff for negative, above it for positive, and one whose size is above it for absolute. The score method's help no longer says that miRNAs with a lower correlation than the threshold are filtered out, which is the opposite of what the default negative selection does. A request that still sends the fold-change selection (`fc`) runs as positive correlation, as it always did, names it so in its results and says why; any other unknown selection method is refused. Messages that read "holds 1 miRNAs", "1 rows of the quantification file had no miRNA id" or "1 of the first 1 unmatched targets differ" now count in agreement.
- Step 2 failed with *Oops..Internal error!* and a Report button when an omic mapped to genes had "%" in its name, such as "RNA 100%", and an omic named like "x%dy" passed Step 2 but showed broken cluster pictures in Step 3. R's picture functions read "%" in a file name as a page-number pattern, so they refused "RNA 100%_cluster_1.png" and saved "x%dy_cluster_1.png" as "x1y_cluster_1.png", which Step 3 never asks for. The metagenes script now draws each picture under a name R picks and then copies it to its real name, which R's copy takes as it is. When that script fails, the error no longer carries the start-up lines of the R packages it loads (mclust's version and citation note, factoextra's "Welcome!").
- Step 3's FDR columns moved as soon as anything was filtered, for two reasons. Step 2 corrected the p-values over every matched pathway, KEGG's global map, Metabolic pathways (01100), included, while a filter corrects over the rows the table shows, which never include the map; Step 2 now leaves the map out too, and hiding only the map is no longer a filter. And a filter corrected each database on its own, while Step 2 corrects all of a job's databases together; a filter now corrects them together as well. On the six pathway examples, hiding one KEGG pathway whose p-value is 1 moved FDR values by up to 0.78, in every database, and on one example 25 FDR BH values crossed 0.05; it now moves them by at most 0.004. The exception is the adjusted combined column of a job with more than one condition, which a filter still recomputes from a different value than the one Step 2 corrected (the user guide says so). New jobs' FDR values move a little: on the six examples by at most 0.036, never more than 4.4 % of the value; on a human KEGG-only test job whose most significant pathway was the map itself, the pathways right behind it rose by up to half (FDR BH 0.0028 to 0.0043). No pathway crossed 0.05 in any of them, though one sitting just under 0.05 can. Raw p-values do not change. Jobs already stored keep the values they were stored with until a filter is applied, and a filter on them now corrects all databases together.
- When a Step 2 worker process died, for example killed by the system because the server ran short of memory, or stopped on an error, the pathways it was testing went missing and the job still finished as a success, with a shorter list and no word about it. A missing pathway looked as if none of your genes or metabolites were in it, and the count of matched pathways shrank with it. The job now fails instead, as an error on our side with Report error, and says how many workers and how many pathways were lost, for example "Pathway enrichment lost 1 of 6 worker processes, and with them the results for 62 of 364 pathways". Step 1's identifier mapping already had this check.
- Step 2 failed with *Oops..Internal error!* and a Report button when an omic mapped to genes had "=" in its name, such as "RNA=seq (x=2)", or a double quote, such as `Prot "A"`. An omic mapped to metabolites never passes its name to that script. The R script that computes the metagenes cut each of its arguments at every "=" and removed every `"`, so it looked for the file `<job folder>/RNA` instead of `<job folder>/RNA=seq (x=2)_matched.txt`. It now cuts an argument at its first "=" only and keeps the value as given. The installer's Reactome step read its arguments the same way, and failed when the path of the data folder held "="; it now reads them as the metagenes script does.
- Eleven messages and controls that still said something untrue, or failed to answer, after the dialog fixes below. A page that had a job open when the job was removed now shows *This job is not available* with no Report button, where it showed the same sentence as an internal error; and the link to a job whose first step failed, opened while the server still holds that run, says nothing was saved, not that jobs are removed after 7 and 14 days. The logo, and Reset on Step 1, ask before starting over only when a job is open or something has been entered, and say which, where they asked about "the current job" on an empty form. A script `index.html` lists that does not arrive, or arrives cut off, is asked for again, twice, and one that never arrives whole is named on the page with a reload button, where the page stayed black. A job whose only data is metabolomics is refused at Step 2 when no compound matched or none is selected, where it finished with 0 pathways and no word why. A Step 3 network answer with nothing in it to draw says the network could not be loaded, with a link to reload, where the card spun for ever. An answer cut off on the way, or that never came, now says *The connection failed* with a link to reload and no Report button, on that card and in the dialogs, where the dialogs said *Oops..Internal error!* and advised clearing the browser cache and a Step 1 upload stayed on *Uploading files...* for ever with the form locked. Only the server's own answer for an invalid session signs you out: a refused file with an identifier reading "User not valid" did it too. A failed update of a job's last-opened date, which retention reads, is now reported by the server, where it answered success. A bare address no longer asks the browser's stored jobs for a "most recent job" with a query that always failed and logged an error on every visit; it still opens a new analysis. The sign-in panel no longer binds a guest-session button it does not draw. The organism picker finds a hybrid by the name as written, *Petunia x hybrida*, where the x was read as a genus initial and nothing was found; *E. coli* works as before.
- Two installer checks that misbehaved at the edges. ### Security

- An uploaded file's name, a My Data file a form points to, and an omic's name can no longer reach outside the user's folder: a name holding "/", "\", "..", a NUL, or a link that leads out of the folder is refused with a "Please check your input files" message on Step 1, the three converters and My Data, where before an upload named "../x" was saved outside it. Steps 3 and 4 also show the omic's name as text everywhere it appears (the colour-by options, the pathway table's headers, the details panel, the visual settings, the heatmap panels and their tooltips, the compound class map's axis title and the feature popup's chart legend), so a shared job can no longer carry markup in it to the people who open the link.
- The two "Oops..Internal error!" dialogs show the server's message as text, whichever route sent it, and so does the AI panel when a walk fails. A message can quote what a request carried, such as a file name too long to save, an omic name the Step 2 R script could not use, an organism code or a number that was not one; any of these could be read as markup by the page before. The server also escapes, or leaves out, the values it repeats itself, for pages that show its answers another way: the example mode and MORE model of the region, miRNA and MORE converters, the pathway ids Step 3 is asked for, the field name of an upload that arrives without its omic name, the hub panel's errors and the AI compound selection's failure text are escaped; a dataset id typed into an example link and a job id on the AI routes are repeated only when they are letters, digits, `.`, `_` and `-`, as every real id is; a cluster number that is not a number is no longer quoted. Step 1 no longer shows `&lt;` where a miRNA file had `<`, because that text is no longer escaped twice. The omic name is text in Step 2's cluster setting and replicate card.
- Values from a link or an uploaded file could be read as markup by the page's dialogs. The server now escapes the job id a link carries, along with the job ids, omic names and unrecognised mode values that the Step 1 to Step 3, hub and replicate routes repeat in their own messages, which also covers a page still open from before this change. Refusals of uploaded files, including those of **From miRNA to Genes**, show their text as text, so an identifier such as `<NA>` no longer disappears from them, and the messages Step 1 shows while it prepares a file show the omic's name as text. Other messages are not covered by this change.
- Path traversal was closed on both routes that took a name from the request: a job id could name a directory tree to delete, and a file name could name a file outside the user's directory.
- Forgeable user identity was fixed, covering both the `userID=0` bypass and reuse of a retired id.
- Session and password-reset tokens are drawn from `secrets` rather than `random`.
- Per-request authorisation guards were added where they were missing: re-running step 2 on someone else's job, writing an image into a job's directory, reading someone else's AI interpretation (#62), and the admin and read-only routes.
- The session check that every other handler in its family performed had been skipped by SaveImage, and is restored.
- Password hashes are no longer sent to the admin users panel, and a password change could land on another user's account.
- AI consent is enforced on the server before anything is sent to the LLM service, and the three other routes around the consent check were closed.
- AI chat replies are sanitised before rendering, and a server error response is parsed rather than evaluated.
- A MongoDB cleanup routine leaked data across users (#12).
- Committed secrets were removed, the live server configuration untracked, and a release-hygiene test now fails the suite if a secret is committed again.
- Dependency upgrades across Flask, Pillow, CairoSVG and the HTTP stack bring in their published security fixes.
