# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

PaintOmics AI has not been cut as a numbered release yet, so everything since
PaintOmics 4 is listed under Unreleased. Entries reference the pull request that
merged them where one exists.

## [Unreleased]

### Added

- A **Download** button on the Step 4 **Global heatmap** panel, offering the whole heatmap as a high-resolution PNG or an editable SVG: every omic drawn, side by side, under its heading and colour scale, with the clustering, the relevance and per-condition stars, row labels and condition names written out in full, a title naming the pathway and job, and a key for the stars. It is drawn on white in either theme and built in the browser. Until now the button sat commented out over a `download()` that threw "Not implemented", and the only way to keep a heatmap was a screenshot of the part that fitted on screen.
- A user-guide page, *Comparing three or more groups*: a three-group mouse RNA-seq and lipidomics example (simulated, with the changed pathways listed), an R script that turns raw counts and lipid intensities into one log2 fold-change column and one relevant list per contrast with DESeq2 and limma, and annotated screenshots of every step on paintomics.org. *Preparing your data* now says how a relevant-features header is recognised and why a `#` header leaves a two-column file a pair list, and the FAQ answers whether more than two groups can be compared.
- A step 1 organism hint: the moment a gene-based data file is picked, PaintOmics checks which installed organism its identifiers fit -- from the identifier convention when it is species-specific, otherwise by asking the mapping index of the commonly used organisms -- fills an empty organism field, and flags a chosen organism the identifiers contradict, with one click to correct it. The step 2 "nothing matched" message names that organism too.
- Five checks every walk interpretation must pass before it is rendered, each a verdict stored with the walk and shown as a chip with its numbers: the walk finds more modules than permuted data does and never steps through a currency metabolite (every edge tiered mechanism or association); the title and summary use a mechanistic verb only where a mechanism statement stands behind it, else code writes a neutral title; feedback reporters and true inhibitors are read the right way round on a curated panel of forty-one regulators, with a sign-flipped counter-hypothesis; every cited paper carries its organism, system and scope from MeSH, an out-of-context paper must be named as such where it is cited, and the paper agent checks the citing sentence against its passage; and the walk is anchored to the perturbed gene the design names, given its known transcription-factor targets (`omnipathInstaller.py --tf-targets` writes `mapping/tf_targets.tsv` from CollecTRI and TRRUST) with every module labelled by its distance and the perturbation stated in the header. A harness (`cli --five-checks`) measures the five offline at production temperatures and reports ranges; a simulated Pten knockout dataset serves the anchor test.
- AI interpretation as an agentic graph walk: one network per organism from KEGG, Reactome (complexes and sets read as their proteins) and OmniPath with the job laid over it, a walker with six tools (scan, plan, step, jump, note, stop), a Writer whose statements separate what the pathway draws from what is built on top of it and cite only papers it retrieved in PubMed's best-match order and read, code and model checks on every statement, and a Narrator that writes a checked Results section with its citations numbered in order of first use. The walk over the whole network is the job's interpretation, queued when Step 2 finishes and shown in the AI panel with its legs, statements and references; a Step 4 **Walk** column walks one pathway on its own map with the design card editable before the walk and the legs drawn on the diagram; the chat reads the walk and can walk a few steps from a gene. Walks share the analysis queue under a cap (one fewer than the workers, two per job), a read-only job's walk is its owner's to replace, and a walk stops when its job is deleted. Agents work in parallel inside a ten-minute budget: a planner, one walker per seed, one Writer per part of the chain, and a paper agent that reads every cited paper and returns the passage stating the claim, which code finds in the paper and the page shows under each reference with the section it came from. On the example job the interpretation cites 26 papers in a 1,900-word Results section in under five minutes. Statements and Results name genes instead of calling them a cluster. A planted-module evaluation and a command-line runner with an HTML report come with it.
- A design card read from the experiment design and the user's column headers, which every AI prompt carries: whether the columns are time points, ordered values or unordered conditions, which omics have no column labels, and the guidance that follows (trajectory words only on an ordered axis). The chat tool `get_gene_timecourse` is now `get_feature_values`, which prints each layer under its own labels and never borrows another omic's.
- Ensembl gene, transcript and peptide identifiers for every installed species whose organism Ensembl or Ensembl Genomes annotates. A genebuild registry (`AdminTools/scripts/common_resources/ensembl_genebuilds.json`) tells the default installer where each organism's cross-reference dumps live, and `ensembl_census.py census|verify` reports, per species, which identifier tables exist and what fraction of sampled Ensembl gene ids reach the KEGG identifier table through the real mapper.
- An AI input-format converter that checks every upload against the server's contract, offers one-click deterministic repairs for mechanical faults, and can rewrite a file the analysis cannot read (#67, #72).
- The MORE regulatory model behind a model chooser in Regulatory Omics, offering PLS1 and MLR on `more-rs`, the Rust engine (#44, #166).
- A Step 3 regulator-target network drawn with Cytoscape.js, with free layout, per-condition colouring, search, spotlight, side panel and exports.
- Regulation-per-condition tables beside that network, a "Find in pathways" hand-off from them into the pathway view, and a user-selectable per-omic minimum variation filter for MORE.
- Multi-condition designs: analyses run across any number of conditions rather than two, with per-condition significance stars in the Step 4 heatmaps, in Metabolite Hub and in Class Activity, and a Stouffer weights panel for the combined p-value.
- Replicate-to-sample aggregation in both the pathway visualization and MORE, with the experiment design drafted from your column headers before a job exists.
- A metabolite class activity analysis drawn as a levelled class map, testing whether a class responds on replicates when the data has them (#96, #101, #105).
- A Step 2 disambiguation step that lets you choose which compound an ambiguous metabolite name meant (#88).
- A metabolite hub network derived from the KEGG graph and drawn in the interface (#89).
- An evidence overlay that draws MORE relationships on the pathway diagram as a provenance-labelled layer (#52), including regulators the diagram itself does not print (#84).
- OmniPath as a fourth pathway database source (#43), rice (osa) as a MapMan species (#42), and installation of custom species from a gene-to-KO annotation table.
- Bundled example datasets built from a seeded, manifest-driven generator, with the pathways the enrichment should recover listed alongside the files, and **Load example** for Regions2Genes, miRNA2Genes and MORE as well as pathway acquisition.
- A dark theme with a toggle in the header, a contents sidebar on the results page that follows the database tab in view, and an organism picker that ranks results by what was typed rather than by prefix match (#75).
- A Docker Compose deployment (nginx/TLS, application, MongoDB), a post-deployment smoke test, an operator runbook, species installation from the command line, and a view of the requests users have sent in, in the admin panel (#54).
- Continuous integration: a pull-request gate, a nightly regression run against recorded baselines, staging deployment on merge, and an on-demand profiling workflow.
- Test coverage that had not existed: an import smoke test over every tracked module, an end-to-end enrichment run against a real installed species, the real R backend instead of a double, and a check that an edited asset gets its cache marker bumped.

### Changed

- A walk interpretation the five checks held back is hidden by default instead of withheld: a note names the checks it did not clear, and **Show the interpretation anyway** opens its Results, references and statements under a warning to read them as hypotheses drawn from the walk and the cited papers, not as findings, in both the AI panel and the Step 4 Walk column; the choice holds for that walk while the page is open, and the chat is told the text is there to open. The *Not a graph artifact* check keeps its pass rule and its measured numbers but reports what it could and could not tell: it now stores the measured and relevant counts, how many edges join two relevant genes against its own fifty permutations (counted by hand on a bladder cancer job: 45 against 27.8 expected over 200 permutations, p = 0.10, where the check's walker found 1 module against 1.1), and `untestable` when no three relevant genes are connected, so no module can form (hsa05219's 4 relevant genes of 22 touch none). Its reason no longer says the data "has no structure a walk could find", and an untestable chip is amber with a "?". On a pathway walk (the Step 4 Walk column) that check is now advisory: a failure shows amber ("!", or "?" when untestable) with a reason saying it hides nothing, and only the other four checks can hide the text, because the user opened a map the enrichment test already flagged (Bladder cancer, p = 0.018) and one map's few relevant genes leave the check little or nothing to measure (hsa05219 is untestable; the FoxO map withheld every run, real ones included). The network walk keeps the blocking rule, which is where its rendering measurement was made, and a pathway walk sealed earlier and held back by that check alone shows without being walked again. Only the permutation half of that check is advisory: a walk that stepped through a currency metabolite (ATP, water, NAD) still fails it outright, red and hidden by default, on either kind of walk. An untestable check's hover says when fewer than three relevant genes are on the map, and the offline harness re-seals its records with the shipped rule, so a pathway re-measurement reports what users see. A walk that also stepped through a currency metabolite keeps the null's reason beside that one, which used to replace it.
- The CSIC gateway's `default/llm` alias (on 2026-09-30, Qwen3.8-Flash-Next) was measured as the model for every LLM call against the pinned `deepseek-ai/DeepSeek-V4-Flash-0731` snapshot, on the same code and the same STATegra example. The alias kept 1 statement and cited 2 papers; the snapshot kept 8 and cited 11. Its thinking mode made it worse: every walk ran into its time budget with nothing kept. So the snapshot stays the model, with the alias as its fallback. `AI_CSIC_MODEL=default/llm` still switches a deployment over, and the fixes that made the walk run on it are kept. `test_every_llm_call_asks_one_model` checks that the template, compose, both env examples, the gateway check and the CI review all name one model.
- A front-end pass of 198 small fixes across every screen: the header, menus and message dialogs; the landing page; Step 1 upload; Step 2 matching; the Step 3 results; the Step 4 pathway view; the AI panel; and the account, tools and storage pages. Most are alignment, spacing and type set in the app's own font rather than Neptune's; dark-theme colours that fell below readable contrast; keyboard and screen-reader access (icon-only controls that were unnamed or unreachable, a collapsed AI panel that stayed in the tab order, nav pills whose accessible name was their whole dropdown); grid columns and toolbars that clipped at 1024px; and wording that promised what the server does not do, such as an AI conversion on a server whose converter is off. Each change has a before/after capture in the pull request's report.
- Everything that sent people to paintomics.uv.es now sends them to paintomics.org, the public instance since the 2026-09-07 cutover: the README badge and link, the security policy, the citation file, the bug-report and organism-request issue templates, the terms and conditions page and the maintainer docs. A guest session shows the address the server stored, returned with the credentials, instead of one the client assembled from a hard-coded domain, so a deployment can name its guests under its own host without splitting the stored address from the displayed one. The "RGmatch example data" entry in the Help menu is gone: it linked an archive that left the repository in #170 and that neither instance serves.
- The application is renamed PaintOmics AI, the successor to PaintOmics 4.
- Navigation moved into the header and the left rail was removed.
- The interface runs on one token-based design system for surfaces, shapes and type, with a single typeface and WCAG AA contrast throughout; the landing page, the application mark and the account dialogs were redrawn, and the ExtJS dialogs, tables and upload controls modernized.
- The running-job spinner was replaced with a progress bar that only moves forward and reports what the job is doing.
- The heatmap colour scale was rebuilt against the range the data actually occupies, and the same ramp now paints the pathway diagrams (#63, #92).
- The platform moved to Python 3.11, Flask 3, and pymongo 4 against MongoDB 7, with the imaging and HTTP stacks upgraded onto versions carrying their security fixes, and dependencies declared in one pinned `requirements.txt` at the repository root.
- The analysis pipeline was profiled and made faster: batched cross-reference lookups, one shared fork-aware MongoDB client, a cached GTF annotation, and metagene R scripts run per omic in parallel (#33).
- Step 2 was rebuilt as one module system — a databases matrix, a levelled class-activity pair, and compound disambiguation inside the grid (#111, #114) — and Browse now lives inside the file field (#110).
- Every Step 1 file row now says whether the job requires that file (#108), and the database checkboxes are drawn from what the server has actually installed.
- Jobs are kept for as long as the interface says they will be, and no longer (#65), and the contact address is now `paintomicsai@gmail.com`.

### Fixed

- A walk read p-values and q-values upside down. Every value under 0.005 was printed `+0.00`, so on a job whose values were `adj.p.Value` the most significant genes were called "flat" and "unchanged" and the summary named the least significant ones as the only signal. Small values are now printed in scientific form (`+3.2e-05`) and read back by the checks in any spelling; a p-value or q-value column is found from its header, every agent is told that smaller means a stronger difference with no direction, the direction checks read no sign from it, and a job with no relevant features but such a column is told which cut-off would give the walk its seeds. A transformed column (`-log10(padj)`, `signed_-log10_pval`) is no p-value: it stays a signed value. In a table that also holds a fold change (limma, DESeq2) only the fold change gives a direction; `AveExpr` no longer reads every gene as "up". An effect named otherwise (`M`, `log2 Ratio`, `estimate`, `diff`) counts as one, a `t`, `stat` or `z` column gives the direction when there is none, and a table with p-values and none of these carries no direction at all. A value that rounds to 0.01 is printed `+0.01`, so a sentence quoting it as 0.01 is not removed.
- Two walks running at once could kill each other with "RuntimeError: Event loop is closed" (paintomics.org, three times on 26-27 Oct; one walk stored "The AI service failed before the walk took a step"): they shared one HTTP connection pool across their event loops. Each event loop now has a client of its own, closed with the loop.
- The gateway's 60 requests/min key was not paced: one walk's Writers and paper agents burst past it, paper agents gave up on 429s, and statements lost their evidence or the whole walk ran out of time before its Results. Every caller in the process now shares one budget, learned from the key's own `x-litellm-key-rpm-limit` header (paced at 54/min) unless `AI_LLM_MAX_RPM` says otherwise; the two transports used to keep separate budgets, and the token bucket allowed twice the setting in a rolling minute. A call whose wait for its slot would spend its own time budget is not sent and fails as out of time, and a slot held by a caller cancelled while it waited is handed back to the next one, as is one held by a paper agent whose Writers' stage has ended. A new limit retunes the pacing without forgetting the slots already handed out. **Draft from column names** waits at most 60 s over both of its attempts, then says it could not draft one, instead of holding one of the site's request threads.
- **Draft from column names** returned the model's reasoning ("The user asks for a description of the experiment design ...") or a half sentence in 7 of 8 probes: its 300-token cap ended the reply before the reasoning did. The draft is now asked for as one JSON field with room to finish, a reply that is still reasoning or cut off is asked again once, and otherwise the page says the AI could not draft one. Stored designs that begin with leaked reasoning are read without it, and one that is reasoning about the drafting task and nothing else is read as no design; a design the user typed that opens "We need to compare ..." is kept. A drafted description that arrived as a complete JSON field is no longer refused for lacking a final full stop. A description opening "First, I ..." is a description.
- The direction check read a sign from regulators the user marked not relevant (RB1 −0.45, MDM2 +0.45 in a bladder-cancer walk) and dropped correct statements, among them "MDM2 is essentially unchanged", which always "reads the same with the values reversed". Only a relevant regulator has a data direction now.
- A Results paragraph was charged with a citation its statement listed only in its fields, never in its words, and the whole Results section was dropped ("paragraph 1 drops [101]"). A paragraph owes the citations its statement makes in its own words. Nor is a paragraph retelling a kept statement refused as "mentioning" a dropped one whose claim opens with the same eight words (a 7-statement E. coli proteomics walk lost its Results that way). The refusal for a job with no feature on the graph now names both causes: identifiers that did not map, or genes on no pathway with drawn interactions.
- A network walk of the public STATegra "miRNA to genes (real)" example failed with "your prompt contains at least 260645 input tokens": its "miRNA unmapped" rows sit on genes as layers, one gene carried 241 of them (28,473 characters), and a walker's every answer printed them all for the node and for up to 40 neighbours. The walk's agents and the chat now see at most 8 members of one omic on a node, relevant members first and then the largest values (a p-value or q-value column never counts), with one line saying how many more there are and how many of those are relevant; the largest seed opening fell from 145,799 to 46,352 characters. The checks, the walk's record and the Walk column still read every layer. A walker whose prompt still outgrows the model's window stops with the legs it has walked, the reason recorded, instead of failing the walk.
- A Results section was dropped when its only fault was a kept statement no paragraph retold ("statement 6 is not covered", a 15-statement S. mutans walk, after the repair failed the same way). Each such statement now gets its own prose, already verified, as its paragraph, after the paragraphs of the statements before it; that prose is pruned and checked as the Narrator's is, the section is kept only if it then passes, and the record says which statements were inserted. A section with any other fault is dropped as before.
- A walk could lose its whole Results section to "paragraph N drops [k], which its statement cites" when the citation had gone with a sentence code itself removed: a survivin meta-analysis sentence citing [80] with three hazard ratios its paper's confirmed passage does not give was removed, and the one-statement section was then refused for lacking [80]. A paragraph whose only sentences carrying a citation were removed for a misquoted value no longer owes that citation, since the claim it supported went too; the statement keeps both in the statements list, and the walk's record lists what was let go. The paragraph alone is excused: another paragraph retelling the same statement still owes the citation. A citation that went with a sentence removed for any other reason (a stray reference beside it, the walker's own words), or one the Narrator never wrote, is still asked for, and a paragraph citing a paper its statement does not cite still fails.
- A walk could fail whole with "The AI service failed while writing the statements (ModelBehaviorError: Tool search_literature is currently disabled for agent Writer.)": a Writer's research closes on its share of the time, and when it closed while the model was answering, the search it had just asked for was refused by the agents library as a model error. That Writer is now asked for its statements from what it has read, as one whose turns ran out is.
- A walk's Results summary sometimes showed the Narrator's own instructions instead of findings: "We walked a graph over recurrent vs primary bladder cancer expression data ... The kept statements are the facts; the prose is mine. I must produce exactly 12 fact paragraphs ...". DeepSeek writes its planning into the first field of its answer, the summary. 5 of the 19 Results sections stored on paintomics.org on 2026-10-28 had such a summary, one of them opening on "Then TP53 (−1.58) and back through ..." because another check had already removed the sentence before it; no title had, and no other summary matches. A summary or title sentence in the instructions' own words is now removed, and when that leaves the summary opening on "Then" or "Next" (not "Next to"), that sentence goes too; the rest of the summary, unchanged, and the paragraphs stay. A removal never asks for a rewrite of its own; when the section's other checks ask for one, the Narrator is also told which summary sentences went. A title left empty gets the title code writes, and the title check records that it did. Walks already stored are read without those sentences, in the Walk column, the AI panel and the chat, without being walked again. A Narrator answer half of whose paragraphs are "..." is asked for again, and reads as unanswered if the second is no better; a "..." paragraph covers no statement and a "..." title gets the title code writes; and a repair asked for only because of the title is not kept when it breaks the body. A 20-statement network walk lost its Results to such placeholders.
- A pathway walk on Bladder cancer (hsa05219) was refused at once with "Pathway hsa05219 draws no interactions a walk can follow", although its map draws 16. The walker's network kept one copy of a gene pair that several KEGG maps draw, tagged with the first map by file name, so on human 16 of the 336 maps that draw relations tagged no edge at all and 125 more kept under half of their own (Carbon metabolism, hsa01200, 8 of 275); mouse lost 17 and 119 the same way. Every edge now carries every map that draws it, so a pathway walk sees its whole map, and reads each edge with the sign and subtype that map draws: 427 human gene pairs carry opposite signs in two maps (NF1 → HRAS is an inhibition on the MAPK map, an activation on the Ras map), and 1,641 are signed in one map and unsigned in another. The walk over the whole network reads one merged edge, where an edge one map draws unsigned takes the sign another map draws, ahead of a Reactome reaction's: NFKBIA → NFKB1 now reads as the inhibition hsa04620 draws, not as +1. The hub graph's own reading of the KGML is unchanged. The cached network moves to `universal_network.v5.json.gz` and is rebuilt on first use.
- A walk's Results section was lost when it retold a cited paper's own numbers. On the Bladder cancer walk of a human job the Narrator kept every citation, yet the check that removes sentences quoting values the walk never recorded took out "FGFR3 mutations were mutually exclusive with RAS mutations (p = 0.001) [5]" and a sentence giving 31.2% and 25.0% of 32 specimens [119]; the section then failed for dropping [5] and [119], the one repair re-sent the same sentences, and the page showed no Results, on both runs of 2026-10-28. A sentence in a statement's paragraph may now quote a value its cited paper states, when that paper's confirmed claim or passage for the statement holds it; the summary, the linking paragraphs and a sentence citing nothing still quote only the walk's values, and a misquoted value beside a citation is still removed. When a cited sentence is removed, the repair is told which sentence went and why. On the Step 4 Walk column, the reason under a check that could not be tested is amber like its "?" chip, not red.
- The AI chat showed the model's reasoning as part of its answer: 39 of the 50 answers stored on paintomics.org opened with text such as "Now I have the data. Let me compose the answer.</think>", some after several paragraphs of planning. DeepSeek-V4-Flash writes its reasoning into the answer and ends it with a bare `</think>`; everything up to the last such tag, and any complete `<think>` block, is now removed from every text answer the LLM client returns, so a JSON answer the model prefixed with its reasoning still parses. Answers already stored are cleaned when the chat replays them to the model; the database is not rewritten.
- The AI interpretation failed on most jobs, the STATegra 5-omics example among them, with "The AI service failed before the walk took a step (Pecam1: loop ended without stop: no tool call; ...)", or kept one or two statements. DeepSeek-V4-Flash writes its reasoning as answer text before it calls a tool, and on a real walk brief that text ran past the turn's token cap (1,500 tokens for the planner and walkers, 4,000 for a Writer) on 11 of 29 planner and walker turns and 6 of 19 Writer turns of one walk: the call never came, and the Agents SDK took the cut-off text for the agent's final answer, so a seed ended unwalked and a Writer went to its finish having read nothing. Every planner, walker and Writer turn is now a tool call (`tool_choice="required"`), and code ends each loop: once the plan is set, the walker has stopped, or a submission is accepted. A Writer's searching and reading close once it has read twice the papers its brief asks for, searched three times per paper or used 60% of its time, after which it can still read a paper its statements cite unread; free to research, Writers searched 30 to 41 times each and none submitted. On the STATegra example the network walk went from 9 legs and 3 statements to 45 legs, 13 statements and a Results section that passed all five checks.
- Every walk on a bacterium or a plant failed with "no seed candidate" (S. aureus, N. gonorrhoeae, E. coli, Streptococcus gordonii and Arabidopsis jobs on paintomics.org in October): their KEGG gene ids are locus tags (SAUSA300_0001, b2029, AT1G01010), and only all-digit ids were laid over the graph. An E. coli job that mapped no gene now walks 67 legs and keeps 11 statements. A job with no feature on the graph, none marked relevant, or no relevant one with a measured neighbour is now told which, instead of "Start it again", which could never succeed.
- A Results section retelling more statements than 2,000 words hold was dropped whole (21 statements in 2,481 words, 17 in 2,215): the word ceiling now follows the statements kept, 150 words each, as the floor already did.
- On `default/llm` every AI walk failed with "The AI service failed while writing the statements (MaxTurnsExceeded: Max turns (30) exceeded)". Its Writers searched and read for all 30 turns (40-50 PubMed searches each, half of them empty) and never submitted. A Writer whose turns run out without an accepted submission is now asked for its statements in the same conversation, with no tools, and the Verifier's objections come back until it accepts or its three submissions are used. A tool call the gateway still returns in that phase is read as the statements it carries, never as a failure. The Verifier now also reads the forms that model writes: a leg as `"e3"`/`"J3"`, and a retrieved paper by its PMID. Before, every statement was refused and every citation dropped; a cite given as a number is told to name the node. One Writer is never briefed for more papers than statements (a one-part walk asked a single Writer for all 24). Every Agents-SDK call now logs its agent, turn and prompt tokens against the context window. On the STATegra metabolomics example the walk peaked at 26,694 tokens, 10% of 262,144.
- paintomics.org killed its only uWSGI worker -- every request in flight, every queued job and the job cache -- whenever a request finished while another thread was still reading an upload: with `post-buffering` on, uWSGI adds the harakiri timeout to the worker's single, thread-shared deadline before each body chunk, and a deadline just reset to 0 became one in 1970. Nine kills between 2026-09-22 and 09-24; two users saw their Step 1 upload fail with "the connection was dropped before any answer". `deploy/uwsgi.ini` no longer sets `post-buffering`.
- A finished job's status answer (about 1 MB gzipped after Step 2) could not reach a slow connection: the poll's 65 s limit counted the whole download, so the answer was cut off still arriving, five times over, and the job reported as unanswered. The limit now counts from the last byte received.
- Gene lists in KEGG's own notation (`fox:FOXG_00001`, `mmu:14679`) matched nothing, because the species databases store the bare gene; the job's own organism prefix is now dropped before mapping.
- Faults the front-end pass turned up. A message dialog's Close and Report error could not take focus, so a keyboard user could not dismiss a message; Tab now stays inside the dialog, because ExtJS's own modal wrap throws. The example job's row in My data lost its Description, Recover and Delete cells to a renderer that threw on "Example Job;". Hiding the pathways network's side rail left the graph drawn at its old width, cut off at the edge: `resizeNetwork` called `forEach` on sigma's renderer map, which is an object. Step 2 opened at Step 1's scroll offset, its p10/p90 lines were solid because of a `dashStyle` typo, and an omic name went into the card heading unescaped. The Step 3 pie drew its wedges in a different order from the filter tree, so wedge and chip colours disagreed. In Step 4, the NCBI Gene link was malformed, the PubMed link did not search for the gene, and the node tooltip's heatmap hid its condition labels. Accept with no row selected threw in the file pickers, and My data's "Search by gene/compound" toggle filtered on fields the grids do not have, emptying them (it is gone).
- The step 1 organism hint answered nothing after the first request on a deployed server: it closed the MongoDB client it shares with the rest of the process. Only visible on pymongo 4, which every deployment runs and the development environment does not.

- The pathway diagram was drawn onto an `<svg>` sized to the fitted image rather than to the card that holds it, so a wide map left the rest of the card blank — 550px of white under "Signaling by VEGF" — and zooming could never reclaim it, because the element itself never grew. The diagram now gets the whole card, centred in it. Two zoom defects went with it: the pan/zoom plugin derived each zoomed view box's `y` from its new *width*, which walked the map off centre, and its eased path painted a view box whose height lagged a whole zoom step behind the rest, so `meet` scaled to the wrong axis and zooming barely moved. Wheel zoom also stopped at 3x, less than half way to a 7190px Reactome raster's own pixels; it now reaches 1:1.
- A graph walk could seal with no Results section when the AI gateway rate-limited it near the end. The paper agent's call runs on a thread the pipeline has to wait for, and a 429 asking for an 84 s wait held the pipeline 54 s past the Writers' deadline, which used up the time kept for the Narrator. The paper agent, the direction check, the sense check and the Narrator now give up by their stage's deadline, the pipeline no longer waits for a thread still running when its stage ends, and the page says when a walk ran out of time, including when the Narrator itself gave up at the deadline, and says when the AI service was rate-limiting the Narrator or did not answer it, instead of saying its Results section failed its checks. A regulator the direction check got no answer for (no time left, or none from the AI service) is shown as not checked rather than checked and consistent, and a statement sent back for contradicting a regulator is dropped unless the re-check answers for that regulator. Whether a call ran out of time is decided by the clock: a gateway that times out with time to spare is reported as the AI service not answering.
- A walk that kept fewer statements than planned had its Results section refused for being short: a Rap1 walk kept 6 statements, the Narrator retold them in 368 words, and the plan's 400-word floor left the page with none. The floor is now 50 words per kept statement, up to the plan's.
- A walk's statements and Results could still narrate the walk in other words ("a network walk from the seed miRNA miR-151-3p", "the seed miRNA mmu-miR-3074-1-3p"), which the check for "cluster" and "the walk" let through. Those forms are refused too; a miRNA's seed region, a plant's seed miRNAs and a kinesin walking along a microtubule are not.
- PubMed titles and abstracts were cut at their first inline markup, so "(IP<sub>3</sub>) receptor" reached the AI as "(IP" and a title with an italic gene name lost its end.
- The container deployment recycled its uWSGI worker in the middle of a job. There is a single worker, and `reload-on-rss` was set to 4096 MB while one large multi-omic job already resides at about 2 GB and the in-process job cache holds recently-touched jobs beside it, so a legitimate working set crossed the ceiling and the worker was recycled mid-run, killing the job. The limit is now 12 GB: several times the working set, yet still below the memory left after mongod's `--wiredTigerCacheSizeGB` and the OS, so uWSGI recycles the worker itself, at a request boundary, before the kernel out-of-memory killer would.
- One status poll that got no readable answer ended the wait for a job that was still running. On paintomics.uv.es a poll for a finishing job took 61 s, nginx answered it with its 504 page, the client showed "Oops..Internal error! Unable to parse the error message", stopped polling, and the job finished two minutes later with nobody watching. Both status polls (the job and the AI interpretation) now retry an answer they cannot read -- a proxy's 502/504 page, an empty body, their own 65 s timeout -- at 5, 10, 20, 40 then 60 s for five minutes before reporting the HTTP status and the link back to the job; a readable refusal is still final. The server keeps a finished job's result until the client acknowledges it or ten minutes pass, so a retry made after the one response carrying the result was lost still gets it instead of "Your job is not on the queue anymore". The three dialogs that said "Unable to parse the error message" now say what the server sent.
- 157 of the 171 species on paintomics.org carried no Ensembl identifiers at all, so an Ensembl gene id from a GTF or an expression matrix resolved nothing on soybean, maize, grape, rice, goat and sixty other organisms while the job reported success. A species without its own resources directory used to get KEGG's conversion lists and nothing else; seven that had one never asked for the Ensembl dump (spo, ddi, pfa, osa, sot), parsed it as comma-separated (dosa) or ran a UniProt pass that could only fail (spo, ddi). Genebuilds that publish no EntrezGene rows are linked to KEGG through the UniProt accessions KEGG maps itself. Identifiers Ensembl Genomes imports with GenBank type prefixes (`gene-Solyc01g080690.3`) are stored in both spellings, so a bare ITAG id matches again. A test pins the registry, the pass order and the parsers.
- In the dark theme, an omic card flagged by the file check painted a near-white title bar under near-white text, so the omic's name and its delete control were invisible at 1.01:1; the card body meanwhile lost its tint entirely, and the flagged file field lost its red border to the theme's blanket form-field rule. All three now follow the theme.
- Every AI feature depended on one pinned gateway model and failed outright when its backend went away (llm.iiia.es, 2026-09-08). Both transports now ask the pinned model first and fall back, in order, to `AI_CSIC_FALLBACK_MODELS` (default: the gateway's `default/llm` alias) when it is not being served, skip a failed model for five minutes, and record the model that actually answered; a plain request that a gateway answers with a 5xx is retried streamed before a model is given up on.
- The AI input converter was off on every Docker deployment whatever `deploy/.env` said: `compose.yaml` never passed `AI_INPUT_CONVERTER` to the container, so each rebuild shipped the code default and every conversion ended, after the sandbox had read the file, in "AI file conversion is not enabled on this server" over a disabled box. The switch is now passed through and documented, the upload strip and the sheet ask the server before starting and say so up front with the manual route, a refused or unanswered turn offers Try again, and the smoke test reports any `.env` setting the container does not see and asks the LLM gateway one question; a nightly job asks it the same question with the key held as a repository secret.
- Every pathway job by an anonymous user or by an account migrated from paintomics.uv.es failed at step 1 with `Permission denied: /data/CLIENT_TMP/<user>/tmp/<jobID>`: the copied job files kept their source uid, and the container entrypoint only checked who owned `/data/CLIENT_TMP` itself, which was already correct, so it never repaired the user directories beneath it. The entrypoint now scans the tree and takes ownership of whatever the app user does not own, and the migration script hands the copied files over as part of the copy.
- The database installer (`DBManager.py`) failed on Python 3.11 before parsing any command: its scriptine parser called `inspect.getargspec`, which 3.11 removed, so every organism install in the container and from the Organisms admin page died with an AttributeError. A compatibility shim restores it and a test runs the CLI on the CI interpreter.
- The message dialog's corners were not filled: its 4px accent was the top border while the other sides were 1px, so the border's inner edge was an ellipse the body's round corner never met, and in the dark theme the body also drew its own lighter border, which peeled away from the corner and left a dark notch behind it. The border is now a uniform hairline, the accent is a background layer clipped to the same curve, and the body border is transparent in both themes.
- Enrichment counting inflated `totalMatched`, changing which pathways were reported as significant.
- Step 3's hub scorer used the enrichment denominator instead of its own, and Benjamini-Hochberg is now applied across the whole p-value vector rather than piecewise.
- Non-finite p-values were carried into the FDR correction and into the combination step, where a single NaN produced a NaN result; they are now dropped first, and the combining statistics were checked against SciPy.
- Multi-condition analyses crashed at four separate p-value sites, were impossible from five conditions upward, propagated the adjusted combined p-value for only one condition instead of all of them, and the Stouffer weights panel could not be operated and blanked the p-values it was meant to reweight.
- Metagene clustering was not reproducible for an identical job and produced identical, lopsided clusters, and an R drop-to-vector bug silently killed metagenes for whole omic and database pairs.
- The pathway interaction network divided matched compounds by the gene count, so a metabolomics-only job drew almost nothing (#113).
- A compound omic reported more mapped features than it contained, and features cloned across databases doubled their omic values.
- Reactome class enrichment was computed and then discarded after every analysis, and features were marked eligible for a hardcoded pair of databases rather than for every database selected.
- An analysis that matched nothing died with a division error, and the metagenes step crashed on an empty file instead of saying nothing matched (#97).
- Dependabot resolved the Python dependency group against the newest interpreter instead of the 3.11 this project pins, so its first pull request proposed a NumPy and a SciPy that cannot install here and took the other twenty bumps down with them; the interpreter is now declared in `.python-version`, and `test_dependencies_declared.py` fails if that file and the seven places CI and the images name an interpreter ever disagree.
- A relevance-file header heuristic that only worked for Arabidopsis was replaced with an organism-agnostic one, and a legacy two-column parser dropped the suffix from every row after the first, costing 14 pathways.
- Identifiers that sit two hops away in the cross-reference graph were unreachable, so features that needed an intermediate database were reported as unmapped (#49), and a symbol lookup returned 38 rows for the 13 genes asked for, duplicating features downstream.
- An empty identifier was used as a join key, and association rows were written without a target gene identifier (#95).
- Gene-based jobs crashed outright on dme, bta, ptr and acs (#85), and four further species had no KEGG table speaking their identifiers (#87).
- MORE truncated regulator identifiers that began with the omic name, and read an empty matrix out of a comma-delimited file or one with duplicate identifiers.
- Reactome pathway views showed the input identifier instead of the matched gene symbol (#37), Step 4 showed TAIR/AGI identifiers instead of symbols, gene symbols containing `#` broke metagene generation (#40), and a species lost its MapMan bins when KEGG had no NCBI gene ID conversion for it (#29).
- The miRNA2Genes example could not run and mislabelled the conditions in its output, and Regions2Genes did not read relevant regions, opened files in the wrong mode, and silenced its own module loggers.
- The pymongo 4 migration of the DAO layer fixed a state in which no job could be saved at all, and a status poll could break the job store; a job is now serialised from a snapshot.
- Two simultaneous submissions lost one job and ran the other twice, a second Step 1 submit is now refused (#30), and a failed job blocked its own id until the server restarted instead of being resubmittable.
- Deleting one job wiped another job's data, and deleting a Regions2Genes or miRNA2Genes job only appeared to delete it.
- A blank line in an input file killed the job, a metabolite file of dashes could take down the server, CSV uploads with a byte-order mark were rejected, and the data-management tools did not apply the encoding handling the main upload does.
- Omics whose files disagreed on their conditions were read one at a time and refused (#99).

### Security

- Path traversal was closed on both routes that took a name from the request: a job id could name a directory tree to delete, and a file name could name a file outside the user's directory.
- Forgeable user identity was fixed, covering both the `userID=0` bypass and reuse of a retired id.
- Session and password-reset tokens are drawn from `secrets` rather than `random`.
- Per-request authorisation guards were added where they were missing: re-running step 2 on someone else's job, writing an image into a job's directory, reading someone else's AI interpretation (#62), and the admin and read-only routes.
- The session check that every other handler in its family performed had been skipped by SaveImage, and is restored.
- Password hashes are no longer sent to the admin users panel, and a password change could land on another user's account.
- AI consent is enforced on the server before anything is sent to the LLM service, and the three other routes around the consent check were closed.
- AI chat replies are sanitised before rendering, and a server error response is parsed rather than evaluated.
- A MongoDB cleanup routine leaked data across users (#12).
- Committed secrets were removed, the live server configuration untracked, and a release-hygiene test now fails the suite if a secret is committed again.
- Dependency upgrades across Flask, Pillow, CairoSVG and the HTTP stack bring in their published security fixes.
