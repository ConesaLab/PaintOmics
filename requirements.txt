# PaintOmics 4 runtime dependencies.
#
# This is the only pip manifest in the tree, and that is enforced by
# src/tests/test_dependencies_declared.py.
#
# PaintomicsServer/src/requirements.txt was a second, conflicting copy (CairoSVG
# 2.4.2 vs 2.7.0, Pillow 8.0.1 vs 10.3.0). It was reduced to a bare
# `-r ../../requirements.txt` include, and then deleted outright on 2026-08-11:
# GitHub's dependency graph could not parse a manifest that only includes
# another one, so it went on serving the last snapshot it had managed to read --
# the 2020 pins - and raised 33 Dependabot alerts against versions nothing had
# installed for months. See the test for the measurement.
#
# Versions are pinned so the container reproduces a configuration that is known
# to run, not merely one that resolves.
#
# PYTHON IS 3.11, and the upper bound is as deliberate as the lower one.
#   >= 3.10  Pillow 12.3.0, CairoSVG 2.9.0 and requests 2.33.0 all declare
#            requires_python >= 3.10. Every security fix for those three was
#            unreachable while the image was on 3.9 -- roughly 20 advisories.
#   <= 3.11  No longer pandas: 3.0.5 ships cp312/cp313 wheels, and the bound
#            is now held by the deployment and the regression baselines rather
#            than by a package. `.python-version` is also what tells dependabot
#            which interpreter to resolve against -- without it, it proposes
#            releases that publish no cp311 wheel and the whole group dies at
#            `pip install` before a test runs (#118).
# Moving off 3.11 is a deliberate exercise -- every baseline in tests/baseline
# is recorded on it -- not something to do as a side effect of a bump.
#
# --- Web framework ---
# These were pinned to the 2020 releases, and the pin was self-justifying: the
# comment here said Python had to stay at 3.9 because Flask 1.1.2 / Werkzeug
# 1.0.1 / Jinja2 2.11.2 / MarkupSafe 1.1.1 do not import on 3.10+. That is true
# of those versions, but it made the old framework the reason the whole image
# could not move, and everything else that needed a newer Python was stuck
# behind it -- Pillow, CairoSVG and requests all ship security fixes that
# require >= 3.10 and were therefore unreachable.
#
# The way out is that the *current* Flask stack still supports 3.9
# (flask >= 3.9, werkzeug >= 3.9, jinja2 >= 3.7), so it could be upgraded in
# place, on the old interpreter, and verified before anything else moved. Doing
# that first removed the reason for the 3.9 pin; the image is on 3.11 now.
#
# Two API removals had to be handled, both in src/tests/test_flask3_compat.py:
#   * flask.json.JSONEncoder / app.json_encoder (removed 2.3) -> app.json
#     provider. The tree carried a shim for this that silently did nothing,
#     leaving the Model serialiser unattached and the JSON API broken.
#   * send_from_directory(attachment_filename=) (removed 2.2) -> download_name=
#
# blinker is new here: Flask 2.3 made signals unconditional, so it is a hard
# dependency rather than the optional extra it used to be.
Flask==3.1.3
Werkzeug==3.1.8
Jinja2==3.1.6
MarkupSafe==3.0.3
itsdangerous==2.2.0
click==8.5.0
blinker==1.9.0

# --- Image and SVG rendering ---
# pycairo is deliberately absent: nothing imports it, it is not installed in the
# working environment, and it needs cairo headers to build. cairosvg renders via
# cairocffi, which needs the libcairo2 shared library at runtime -- the container
# must install it.
#
# CairoSVG 2.9.0 and Pillow 12.3.0 are the versions that clear the advisories
# against these two -- 20-odd for Pillow alone -- and both require Python >=
# 3.10, which is what the interpreter move above is for.
#
# defusedxml is not incidental here. CairoSVG parses with
# forbid_entities/forbid_external unless unsafe=True, and that is what
# renderSvgToPng relies on; see test_svg_export_is_sandboxed.py.
#
# tinycss2, cssselect2 and defusedxml were pinned to 2019-era releases that
# CairoSVG 2.9 does not work against. CairoSVG declares them without bounds, so
# these pins are the resolved versions, recorded rather than left to float.
CairoSVG==2.9.0
cairocffi==1.7.1
Pillow==12.3.0
tinycss2==1.5.1
cssselect2==0.10.1
webencodings==0.6.1

# --- Input handling ---
# chardet detects the encoding of uploaded omics files
# (classes/JobInstances/PathwayAcquisitionJob.py). Also undeclared: the app
# failed to boot in a clean container with ModuleNotFoundError.
#
# HELD AT 5.x DELIBERATELY -- do not let a bot walk this forward. chardet 6/7
# replaced the 5.x scoring model and its confidence for single-byte codecs
# collapsed: a latin-1 omics table that 5.2.0 calls ISO-8859-1 at confidence
# 0.73, 7.6.0 calls hp-roman8 (or Windows-1250, depending on the sample) at
# 0.05. Util.ensure_utf8 trusts the guess, and those codecs accept every byte,
# so the cp1252/latin-1 fallback chain never triggers: the upload is rewritten
# in place, mojibaked, and the function reports success. Measured on a 17-row
# Spanish annotation table: 0 rows wrong on 5.2.0, 6 wrong on 7.6.0
# (N->N-acute, i-diaeresis->d-caron, A-ring->L-acute). Reachable from
# PathwayAcquisitionJob, Bed2GeneJob, MiRNA2GeneJob and MOREServlet, and
# invisible to test_ensure_utf8 / test_input_encoding / test_dm_upload_encoding,
# which all pass on both versions. `ignore` in .github/dependabot.yml keeps the
# bot off it; revisit only with a detection test that covers latin-1 tables.
chardet==5.2.0

# --- AI interpretation pipeline (src/classes/AIInterpret/) ---
openai==3.8.0
openai-agents==0.22.0
# Imported directly by AIInterpret/agent.py (Timeout for the SDK client,
# HTTPError while iterating a completion stream -- openai wraps only the
# initial request, so a mid-stream failure arrives as a raw transport error).
#
# openai 3.x renamed that transport: it declares httpx2 and does not depend on
# httpx at all, and the two share no class hierarchy -- httpx2.ReadError is not
# an httpx.HTTPError. agent.py binds whichever is installed and catches both,
# so both are declared here. httpx stays pinned because agent.py still imports
# it by name; httpx2 is pinned because it is now the one openai actually
# raises from, and nothing else in the manifest would hold it still.
httpx==0.28.1
httpx2==2.12.0
# No longer strictly required, and kept deliberately. openai-agents' models use
# PEP 604 annotations ("float | None"), which pydantic cannot evaluate before
# 3.10 without this backport -- on 3.9, `import agents` raised TypeError at
# import time, and openai-agents does not declare the dependency itself. On
# 3.11 the annotations evaluate natively, so this is inert.
#
# It stays because it is inert rather than wrong: dropping it buys nothing and
# would silently reintroduce the import failure for anyone running the tree on
# 3.9, which the test suite still does. Remove it only when 3.9 is no longer
# supported anywhere.
eval_type_backport==0.4.0

# --- Scheduling and utilities ---
# setuptools was pinned <81 because APScheduler 3.6.3 imported pkg_resources at
# module load (apscheduler/__init__.py: from pkg_resources import
# get_distribution), and setuptools 81 deprecated it, 82 removed it: a clean
# image died at start-up with ModuleNotFoundError. APScheduler 3.11.3 uses
# importlib.metadata instead, so that reason is retired and nothing in the tree
# imports pkg_resources any more. The bound is kept one major back of nothing
# in particular -- it buys a deliberate look at the next setuptools major
# rather than a surprise -- and 3.11's own ensurepip seeds a version well
# inside it. APScheduler 4.x changes the API, so this is not that upgrade.
setuptools<85
APScheduler==3.11.3
psutil==7.2.2
python-dateutil==2.9.0.post0
pytz==2026.3.post1
# Moves as a pair with APScheduler: 3.11.3 requires tzlocal>=3.0, and tzlocal 3
# returns a zoneinfo where 2.x returned a pytz tzinfo. Safe here because the
# tree never calls .localize() or get_localzone() itself -- it hands APScheduler
# an interval trigger and lets the library own the timezone object.
tzlocal==5.4.4
six==1.17.0
